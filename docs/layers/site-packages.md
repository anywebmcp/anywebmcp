# Site packages layer

`packages/sites/*` contains one package per supported website. The normative [site package standard](../site-package-standard.md) defines cross-package boundaries, safety invariants, and delivery obligations; this layer document only summarizes where website-specific behavior lives.

Each package owns:

- Supported domains and documented page preconditions.
- WebMCP tool definitions.
- Page context and selectors.
- UI, official API, or internal API adapters.

The X package lives at `packages/sites/x`. It reads posts from the DOM, captures GraphQL activity for diagnostics, and returns prefilled posting and reply intent URLs for users to review and submit manually.

The LinkedIn package lives at `packages/sites/linkedin`. It reads the virtualized feed through bounded DOM scans and scrolling, keeps stable references to recently observed posts, and can insert a verified comment draft for manual review without submitting it.

The eBay package lives at `packages/sites/ebay`. It performs bounded same-origin searches and item reads with the current regional eBay session, prefers schema.org product data and stable listing IDs, and changes watch state only through a mounted, verified eBay UI control.

The Temu package lives at `packages/sites/temu`. It reads bounded product-search results and product details from the rendered DOM or public page HTML, keeps recently observed product references, and compares same-currency displayed prices without modifying the cart or starting checkout.

The standard contains a recommended package tree without prescribing concrete directory names. Each package README documents site-specific domains, page contexts, tools, selectors and endpoint assumptions, limits, and constraints. Benchmark results follow the separate [benchmarking process](../benchmarking-site-tools.md).
